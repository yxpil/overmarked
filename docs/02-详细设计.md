# OVERMARKED 详细设计

版本 1.0 · 2026-10-22 · 与代码基线 `server/` `public/` 对应

---

## 1. 运行环境与配置

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8787` | HTTP 端口 |
| `HOST` | `127.0.0.1` | 监听地址；内网共享用 `0.0.0.0` |
| `DATA_DIR` | `./data` | 数据库与上传文件根目录，自动创建 |
| `ADMIN_PASSWORD` | 空 | 首次启动播种 admin 的密码；空则随机生成 |
| `ADMIN_USERNAME` | `admin` | 首次启动管理员用户名 |
| `SESSION_DAYS` | `7` | 会话有效期（天） |
| `UPLOAD_MAX_MB` | `512` | 单文件上限（MB） |
| `TEXT_MAX_MB` | `10` | 文本文件上限（MB） |
| `TRUST_PROXY` | `0` | 为 `1` 时信任 `X-Forwarded-For` 第一跳 |
| `COOKIE_SECURE` | `0` | HTTPS 部署时设 `1` |

启动顺序：解析配置 → 创建数据目录 → 打开 SQLite（WAL + 外键 + busy_timeout）→ 执行 DDL → 清理过期会话 → 若 `users` 为空则播种管理员 → 启动 HTTP。

优雅退出：`SIGINT/SIGTERM` 时停止接收新连接，关闭数据库后退出。

## 2. 数据库设计

### 2.1 DDL

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;

CREATE TABLE IF NOT EXISTS schema_meta (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS users (
  id            TEXT PRIMARY KEY,                 -- uuid
  username      TEXT NOT NULL UNIQUE COLLATE NOCASE,
  display_name  TEXT NOT NULL,
  password_hash TEXT NOT NULL,                    -- scrypt$N$r$p$saltB64$hashB64
  role          TEXT NOT NULL DEFAULT 'user'
                CHECK (role IN ('admin','user')),
  status        TEXT NOT NULL DEFAULT 'active'
                CHECK (status IN ('active','disabled')),
  created_at    TEXT NOT NULL,                    -- ISO-8601 UTC
  last_login_at TEXT
);

CREATE TABLE IF NOT EXISTS sessions (
  token_hash TEXT PRIMARY KEY,                    -- sha256(token) hex
  user_id    TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  created_at TEXT NOT NULL,
  expires_at TEXT NOT NULL,
  ip         TEXT,
  user_agent TEXT
);
CREATE INDEX IF NOT EXISTS idx_sessions_expiry ON sessions(expires_at);
CREATE INDEX IF NOT EXISTS idx_sessions_user   ON sessions(user_id);

CREATE TABLE IF NOT EXISTS projects (
  id           TEXT PRIMARY KEY,
  name         TEXT NOT NULL,
  description  TEXT NOT NULL DEFAULT '',
  kind         TEXT NOT NULL CHECK (kind IN ('image','text','audio','spatial')),
  label_schema TEXT NOT NULL,                     -- JSON，见 3.2
  archived     INTEGER NOT NULL DEFAULT 0,
  created_by   TEXT NOT NULL REFERENCES users(id),
  created_at   TEXT NOT NULL,
  updated_at   TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS project_members (
  project_id TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  user_id    TEXT NOT NULL REFERENCES users(id)    ON DELETE CASCADE,
  role       TEXT NOT NULL CHECK (role IN ('manager','reviewer','annotator')),
  created_at TEXT NOT NULL,
  PRIMARY KEY (project_id, user_id)
);
CREATE INDEX IF NOT EXISTS idx_members_user ON project_members(user_id);

CREATE TABLE IF NOT EXISTS items (
  id            TEXT PRIMARY KEY,
  project_id    TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  seq           INTEGER NOT NULL,                 -- 项目内自增展示序号
  original_name TEXT NOT NULL,
  storage_key   TEXT NOT NULL,                    -- '<uuid>.<ext>'，相对 uploads/<projectId>/
  mime          TEXT NOT NULL,
  size          INTEGER NOT NULL,
  meta          TEXT NOT NULL DEFAULT '{}',       -- JSON，见 3.3
  status        TEXT NOT NULL DEFAULT 'pending'
                CHECK (status IN ('pending','in_progress','submitted','approved','rejected')),
  assignee_id   TEXT REFERENCES users(id) ON DELETE SET NULL,
  uploaded_by   TEXT REFERENCES users(id) ON DELETE SET NULL,
  created_at    TEXT NOT NULL,
  updated_at    TEXT NOT NULL,
  UNIQUE (project_id, seq)
);
CREATE INDEX IF NOT EXISTS idx_items_queue ON items(project_id, status, seq);
CREATE INDEX IF NOT EXISTS idx_items_assignee ON items(assignee_id);

CREATE TABLE IF NOT EXISTS annotations (
  item_id     TEXT PRIMARY KEY REFERENCES items(id) ON DELETE CASCADE,
  project_id  TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  data        TEXT NOT NULL,                      -- JSON，见 3.4
  status      TEXT NOT NULL
              CHECK (status IN ('draft','submitted','approved','rejected')),
  version     INTEGER NOT NULL DEFAULT 1,
  created_by  TEXT NOT NULL REFERENCES users(id),
  updated_by  TEXT NOT NULL REFERENCES users(id),
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL,
  submitted_at TEXT,
  reviewed_at  TEXT
);
CREATE INDEX IF NOT EXISTS idx_annotations_project ON annotations(project_id, status);

CREATE TABLE IF NOT EXISTS annotation_versions (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  item_id    TEXT NOT NULL REFERENCES items(id) ON DELETE CASCADE,
  version    INTEGER NOT NULL,
  data       TEXT NOT NULL,
  status     TEXT NOT NULL,
  author_id  TEXT NOT NULL REFERENCES users(id),
  created_at TEXT NOT NULL,
  UNIQUE (item_id, version)
);

CREATE TABLE IF NOT EXISTS reviews (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  item_id     TEXT NOT NULL REFERENCES items(id) ON DELETE CASCADE,
  reviewer_id TEXT NOT NULL REFERENCES users(id),
  decision    TEXT NOT NULL CHECK (decision IN ('approved','rejected')),
  note        TEXT NOT NULL DEFAULT '',
  created_at  TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_reviews_item ON reviews(item_id, id);

CREATE TABLE IF NOT EXISTS audit_log (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  actor_id   TEXT,
  action     TEXT NOT NULL,                        -- 'project.create' 等
  entity     TEXT NOT NULL,                        -- 'project' | 'item' | ...
  entity_id  TEXT,
  project_id TEXT,
  detail     TEXT NOT NULL DEFAULT '{}',
  ip         TEXT,
  created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_audit_project ON audit_log(project_id, id DESC);
CREATE INDEX IF NOT EXISTS idx_audit_actor   ON audit_log(actor_id, id DESC);
```

### 2.2 时间、ID、事务

- 所有 id 为 `crypto.randomUUID()`；审计自增 id 除外。
- 时间统一 `new Date().toISOString()`（UTC，毫秒精度）。
- 写操作使用 `db.exec('BEGIN IMMEDIATE')` / `COMMIT` / `ROLLBACK` 包裹（同步 API），失败回滚。
- seq 分配在事务内：`SELECT COALESCE(MAX(seq),0)+1 FROM items WHERE project_id=?`。
- 删除项目依赖外键级联，再删除 `uploads/<projectId>` 目录（先删文件再删数据库行，失败时数据库仍保留记录便于重试）。

### 2.3 迁移策略

v1 使用 `schema_meta.version = 1`。启动时执行幂等 DDL；未来结构变更通过递增版本并执行迁移函数。备份建议：复制 `data/overmarked.db*` 与 `data/uploads/`。

## 3. JSON 结构规范

### 3.1 项目标签体系 `projects.label_schema`

```json
{
  "labels": [
    { "id": "lb_1", "name": "行人", "color": "#f5a524", "hotkey": "1" }
  ],
  "documentLabels": [
    { "id": "dl_1", "name": "正面", "color": "#7dd3fc" }
  ]
}
```

校验规则：

- `labels` 1..64 项；`documentLabels` 0..32 项（仅文本项目使用）。
- `id` 匹配 `^[a-z0-9][a-z0-9_-]{0,31}$`，项目内唯一。
- `name` 去空白后 1..40 字符，项目内不区分大小写唯一。
- `color` 匹配 `^#[0-9a-fA-F]{6}$`。
- `hotkey` 可选，单个字符 `[1-9a-zA-Z]`，项目内唯一。
- 新增默认标签：图片"目标"、文本"实体"、音频"片段"、空间"区域"；颜色 `#f5a524`。

### 3.2 条目元数据 `items.meta`

```json
{
  "width": 1920, "height": 1080,          // 图片（服务端解析）
  "duration": 12.48,                       // 音频时长（客户端解码后回填）
  "bounds": [-122.52, 37.70, -122.35, 37.82],
  "crs": "EPSG:4326",                      // 或 "pixel"
  "featureCount": 12                       // GeoJSON 底图要素数
}
```

`PATCH /items/:id` 只接受 meta 白名单键并做范围校验；`bounds` 顺序为 `[west, south, east, north]`，`west<east`、`south<north`。

### 3.3 标注数据 `annotations.data`

统一外壳：`{ "<集合字段>": [...], "note": "string" }`。所有图元 `id` 为客户端 `crypto.randomUUID()`；`label` 必须引用当前 schema 中存在的标签 id。

图片：

```json
{
  "shapes": [
    { "id": "s1", "type": "box", "label": "lb_1", "x": 120, "y": 80, "w": 200, "h": 160 },
    { "id": "s2", "type": "polygon", "label": "lb_1", "points": [{"x":10,"y":10},{"x":90,"y":20},{"x":40,"y":80}] }
  ],
  "note": ""
}
```

坐标单位为原图像素；框 `w>0,h>0`；多边形至少 3 点；服务端限制图元总数 ≤ 5000。

文本：

```json
{
  "entities": [ { "id": "e1", "start": 3, "end": 5, "label": "lb_1" } ],
  "documentLabels": ["dl_1"],
  "note": ""
}
```

`0 ≤ start < end ≤ 文本长度`，服务端读取文件计算长度；实体之间不允许部分重叠（可相邻）。上限 2000 个实体。

音频：

```json
{ "segments": [ { "id": "a1", "start": 1.25, "end": 3.8, "label": "lb_1" } ], "note": "" }
```

单位秒，`start ≥ 0`，`end > start`，`end ≤ duration + 0.05`（若已知 duration）；上限 2000 段。

空间：

```json
{
  "features": [
    { "id": "f1", "label": "lb_1",
      "geometry": { "type": "Point", "coordinates": [121.47, 31.23] } },
    { "id": "f2", "label": "lb_1",
      "geometry": { "type": "LineString", "coordinates": [[121.4,31.2],[121.5,31.25]] } },
    { "id": "f3", "label": "lb_1",
      "geometry": { "type": "Polygon", "coordinates": [[[121.4,31.2],[121.46,31.2],[121.45,31.26],[121.4,31.2]]] } }
  ],
  "note": ""
}
```

只允许 `Point | LineString | Polygon`；坐标数组按 GeoJSON RFC 7946 顺序 `[x, y]`；像素坐标系同样使用该结构。上限 3000 个要素。

**通用限制**：data 序列化后 ≤ 4 MB；`note` ≤ 2000 字符。

### 3.4 标注版本与审核记录

- `annotations.version` 每次成功保存 +1。
- `annotation_versions` 在**提交**和**复核决定**时写入快照（草稿不写历史，避免噪音）。
- `reviews` 记录每次通过/驳回意见，供标注人查看与审计。

## 4. 认证与会话

### 4.1 密码哈希

格式 `scrypt$16384$8$1$<saltBase64>$<hashBase64>`，keyLen 64，salt 16 字节。

```
hash = scrypt(password, salt, 64, { N: 16384, r: 8, p: 1, maxmem: 64MB })
verify: 解析参数 → 重新计算 → crypto.timingSafeEqual
```

密码策略：8..128 字符。登录时用户名按 trim + 小写查询；不存在用户也执行一次假哈希（固定盐）以减弱时序差异。

### 4.2 会话

- 登录成功：`token = randomBytes(32).toString('base64url')`；`sha256(token)` 存库；Cookie `om_session=<token>`，`HttpOnly; SameSite=Strict; Path=/; Max-Age=<SESSION_DAYS*86400>`，`COOKIE_SECURE=1` 时加 `Secure`。
- 每次请求：解析 Cookie → 摘要查库并 join users → 检查未过期、用户 `active`；滑动续期可选（v1 不续期）。
- 登出：删除当前会话行并清 Cookie。
- 改密/管理员重置/停用：删除该用户全部会话。
- 启动与每 6 小时清理 `expires_at < now`。

### 4.3 CSRF 与来源

- Cookie `SameSite=Strict` 已阻断跨站表单携带。
- 所有非 GET/HEAD 的 `/api/*` 请求必须带 `X-OM-Request: 1`，否则 `403 CSRF_BLOCKED`。
- 不校验 Origin 以保证 `curl` 与内网 IP 访问兼容。

### 4.4 登录限流

内存 `Map<key, {count, resetAt}>`，key=`ip|username`。窗口 10 分钟，阈值 8 次失败。成功后清空。超限返回 `429 RATE_LIMITED` 与 `Retry-After`。定时清理过期项。

## 5. 授权实现

`acl.js`：

```js
getMembership(db, projectId, userId) -> {role} | null
assertProjectAccess(ctx, projectId, need)  // need: 'view'|'annotate'|'review'|'manage'
```

- `need=view`：admin 或成员。
- `need=annotate`：admin、manager、reviewer、annotator（即任何成员）都允许；归档项目拒绝写入（`PROJECT_ARCHIVED`）。
- `need=review`：admin、manager、reviewer。
- `need=manage`：admin、manager。
- 删除项目：admin 或 manager；`DELETE` 二次确认由前端负责，服务端要求 body `{confirmName}` 与项目名一致，防误删。

路由层统一通过 `ctx.requireProject(id, need)` 获取 `{project, role}`；所有条目/标注路由先由条目查得 `project_id` 再断言。

## 6. 上传与文件服务

### 6.1 允许类型

| 项目类型 | 扩展名 | 存储 MIME |
|---|---|---|
| image | png, jpg, jpeg, webp, gif | image/png, image/jpeg, image/webp, image/gif |
| text | txt, md, csv, json, jsonl | text/plain（响应时强制） |
| audio | wav, mp3, ogg, m4a, aac, flac, webm | 对应 audio/*（webm→audio/webm） |
| spatial | geojson, json, png, jpg, jpeg, webp | application/geo+json 存 raw，响应 json/png 等 |

- 客户端声明 `Content-Type` 不参与信任判断；以扩展名映射为准。
- 文本大小上限取 `TEXT_MAX_MB`；其余取 `UPLOAD_MAX_MB`。
- 原始文件名去除路径与不可见字符，仅保留展示；超长截断 200 字符。

### 6.2 上传流程

1. `POST /api/projects/:id/items?filename=<urlencoded>`。
2. 鉴权 `annotate` + 项目未归档；校验扩展名。
3. 校验 `Content-Length` 非零且不超限（无长度则边写边计数，超限中断）。
4. 写入 `data/uploads/<projectId>/<uuid>.<ext>.part`，同步计数并计算。
5. 按类型后处理：图片解析宽高；GeoJSON 解析包围盒与要素数（失败则删除临时文件并 `422`）。
6. `rename` 为最终存储键；事务内分配 seq、插入 items。
7. 返回条目 JSON；审计 `item.upload`。

并发上传同一项目时，seq 分配由 `BEGIN IMMEDIATE` 串行化。

### 6.3 下载与 Range

`GET /api/items/:id/file`：

- 先鉴权，再 `readFile`/`createReadStream`。
- 文本强制 `text/plain; charset=utf-8`；GeoJSON 底图用 `application/json; charset=utf-8`；图片/音频用存储 MIME。
- 响应头：`Content-Length`、`Accept-Ranges: bytes`、`Cache-Control: private, max-age=3600`、`X-Content-Type-Options: nosniff`。
- `Range: bytes=a-b` → 解析、裁剪、`206` + `Content-Range: bytes a-b/total`；`a>=total` 或格式错误 → `416` + `Content-Range: bytes */total`。
- 多段 Range 不支持，忽略并返回 200（文档说明）。

### 6.4 图片尺寸解析

- PNG：签名校验后读 IHDR：宽 `UInt32BE(16)`，高 `UInt32BE(20)`。
- JPEG：遍历段，遇 `0xFFC0..0xFFC3 / 0xFFC5..0xFFC7 / 0xFFC9..0xFFCB / 0xFFCD..0xFFCF`（SOF）读高 `UInt16BE(p+5)`、宽 `UInt16BE(p+7)`。
- GIF：`UInt16LE(6)`、`UInt16LE(8)`。
- WebP：`RIFF....WEBP`；`VP8X` → 24 位宽高各 +1；`VP8 ` → 帧头 14 位宽高；`VP8L` → 位打包宽高。解析失败不阻断上传，meta 不写尺寸（前端加载后回填）。

### 6.5 GeoJSON 解析

- 接受 FeatureCollection / Feature / Geometry；递归遍历 `coordinates`（含 GeometryCollection / Multi*），得到 `[west,south,east,north]`。
- 校验坐标数值有限、经度 [-180,180]、纬度 [-90,90]；空几何允许但无 bounds。
- 写入 `meta.bounds`、`meta.crs='EPSG:4326'`、`meta.featureCount`。

## 7. 业务规则

### 7.1 项目

- 创建：任何已登录用户可创建；名称 1..80；描述 ≤ 2000；kind 只读。
- 创建者写入 `project_members` 为 manager；审计。
- 修改项目（名称/描述/标签体系/归档）需 `manage`。标签体系更新时，**不允许删除仍被标注引用的标签**（扫描当前 annotations.data），否则 `409 LABEL_IN_USE`；改名/改色允许。
- 删除：`manage` + body.confirmName 精确匹配；删除文件目录与记录。

### 7.2 成员

- 增加成员：目标用户必须存在且 active；不能把 disabled 用户加入；管理员可加入自己（无副作用）。
- 修改角色 / 移除：不能移除项目最后一名 manager（除非系统管理员操作或另有 manager）。
- 成员变更审计。

### 7.3 条目

- 列表默认按 seq 升序，分页 `page`（1 起）+ `limit`（默认 50，最大 200）；过滤 `status`、`q`（原始文件名 LIKE，转义 `%_`）、`assignee=me|<userId>`。
- 指派：`manage` 或 annotator 自领（`assigneeId=self`）；指派对象必须为项目成员。
- 状态手工修改仅 manager：允许 `approved→in_progress`、`rejected→in_progress`、`submitted→in_progress`（撤回提交）。其他方向由标注/审核流程驱动。
- 删除条目：`manage`；删除标注级联与文件；审计。

### 7.4 标注保存

`PUT /api/items/:id/annotation`：

1. 鉴权 `annotate`（归档项目拒绝）。
2. 条目状态：`approved` 且调用者非 manager → `409 ITEM_APPROVED`。
3. 校验 data 结构与标签引用；文本项目计算文件 UTF-8 长度校验区间。
4. 若 `submit=true`：annotation.status=`submitted`、`submitted_at`、item.status=`submitted`；写版本快照。
   若 false：annotation.status=`draft`；item.status=`pending→in_progress`（rejected/submitted 保持语义：保存草稿会把 submitted 拉回 in_progress，并在审计记录）。
5. upsert annotations（version+1），审计 `annotation.save|annotation.submit`。
6. 返回 `{annotation, item}`。

同一用户重复提交允许覆盖；其他成员保存会覆盖同一标注（协作者共享），由审计区分。

### 7.5 复核

`POST /api/items/:id/review`：

- 鉴权 `review`；条目必须 `submitted`，否则 `409 INVALID_STATE`。
- 决定 `approve|reject`；reject 时 note 必填（1..2000）。
- 更新 annotation.status、item.status、reviewed_at；写 reviews、版本快照；审计。
- 已通过后再次复核拒绝（撤销通过）仅 admin/manager：若 item=approved，允许 review 再次执行（`INVALID_STATE` 例外），记录新 review，状态改为 rejected。

### 7.6 统计

`GET /api/projects/:id/stats` 返回：

```json
{
  "total": 120,
  "byStatus": {"pending":50,"in_progress":10,"submitted":20,"approved":35,"rejected":5},
  "approvedPct": 29.2,
  "annotators": [{"userId":"...","name":"...","annotated":40,"approved":38}],
  "labels": [{"labelId":"lb_1","name":"行人","count":133}],
  "trend": [{"date":"2026-10-21","submitted":12,"approved":9}]
}
```

- annotators 按 annotation.updated_by 聚合；labels 扫描 annotations.data（所有非 draft 版本）。
- trend 取最近 14 天，按审计/版本时间近似统计；v1 从 annotation_versions + reviews 聚合。
- 非成员不可访问。

### 7.7 导出

`GET /api/projects/:id/export?format=coco|raw|ner|audio|geojson&scope=approved|all`。

- 默认 `scope=approved`；只有 `approved` 条目进入标准格式。`raw` 包含项目、条目、当前标注与 review 摘要。
- 文件名：`<project-name>-<format>-<yyyymmdd>.json[l]`，名称 slug 化；响应附件下载；审计 `export.download`。
- 图片 `coco`：只导出 box 的 bbox；polygon 计算外接 bbox 与 `segmentation`；类别 id 为 schema 顺序（1 起）。无标注条目不进入 images。
- 文本 `ner`：JSONL，每行 `{id, filename, text, entities:[{start,end,label}], documentLabels:[names]}`；文本读取失败则该行带 `error` 字段但不中断（v1 直接失败并提示）。
- 音频 `audio`：JSONL `{id, filename, duration, segments:[{start,end,label}]}`。
- 空间 `geojson`：FeatureCollection，每个标注要素 → Feature，`properties={label, labelName, itemId, seq, filename}`；`crs` 属性标注坐标系。
- `format=raw` 任何项目可用。

## 8. 前端设计

### 8.1 结构与路由

- 单页应用，Hash 路由：`#/login`、`#/projects`、`#/p/<id>`、`#/p/<id>?item=<itemId>`、`#/admin`。
- 无框架。`app.js` 维护 `state = {user, projects, project, items, currentItem, annotation, role}`。
- 视图模块导出 `render(root, params)` / 清理函数；标注器导出统一接口：

```js
createImageAnnotator(el, {item, data, schema, readOnly, onChange})
  -> { getData(), setLabel(id), destroy(), focus(id) }
```

- API 客户端统一：非 GET 加 `X-OM-Request: 1`；`401` 跳登录；错误抛出 `ApiError{code,message,status,details}`，UI toast。

### 8.2 视觉系统（自定义，无外部资源）

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#0c0e10` | 页面底色 |
| `--panel` | `#14171a` | 面板 |
| `--panel-2` | `#1a1e22` | 浮层/输入 |
| `--line` | `#262b30` | 1px 分隔线 |
| `--text` | `#e8eaed` | 主文本 |
| `--muted` | `#8b949e` | 次级文本 |
| `--accent` | `#f5a524` | 主操作/选中 |
| `--danger` | `#ef5b5b` | 驳回/删除 |
| `--ok` | `#48c78e` | 通过 |
| 字体 | `ui-sans-serif, "Segoe UI", "PingFang SC", "Microsoft YaHei"` | 界面 |
| 等宽 | `ui-monospace, "Cascadia Code", Consolas` | 数据、编号 |

规则：4/8px 间距栅格；圆角统一 4px（对话框 6px）；无渐变、无毛玻璃、无装饰插画；数字与 ID 用等宽字体；状态用色点 + 文案而非仅颜色；焦点环 2px accent。

### 8.3 图片标注器

- 数据坐标 = 原图像素；视口变换 `screen = world * scale + t`。
- 初始 fit：`scale=min(vw/iw, vh/ih)*0.95` 居中；缩放范围 0.05..16。
- 滚轮以指针为锚点缩放；空格 + 拖拽 / 中键平移。
- 工具：`select`、`box`、`polygon`。
- 框：拖拽创建；选中后 8 个手柄缩放；内部拖动移动。
- 多边形：单击落点，双击/Enter 闭合（≥3 点），Esc 取消；选中后可拖动顶点。
- 命中测试在世界坐标做，容差 6px/scale；选择顺序取最上层。
- 标签继承当前选中的标签；选中图元时切换标签会改色。
- 渲染：每个标签颜色描边 + 半透明填充；选中白色虚线 + 顶点方块；标签名绘制在左上角，带深色底。
- 缩放 UI 显示百分比；适配按钮；快捷键 `V/B/P`，数字选标签，Delete 删除，Esc 取消。

### 8.4 文本标注器

- 拉取 `/file` 文本，构建 `textContent` 安全的段落；实体渲染为 `<mark>` 片段（颜色由标签决定），不用 `innerHTML`。
- 鼠标选择 → 浮动标签选择条 → 应用实体；计算绝对偏移：Range 从容器起点到选区起点的 `toString().length`。
- 禁止部分重叠：插入前检查 `[start,end)` 与现有实体交集；完全包含/相交均拒绝并提示。
- 实体列表按 start 排序；点击滚动定位并高亮；可删除。
- 文档级标签为 toggle 芯片，存 `documentLabels`。
- 快捷键：数字应用当前标签到选区；Delete 删除选中实体。

### 8.5 音频标注器

- `/file` → `arrayBuffer` → `AudioContext.decodeAudioData`（失败给出可读错误与格式建议）。
- 波形：取声道 0（多声道取平均）按画布列计算 min/max 峰值；画布宽度变化时重算；颜色 `#3a424a` 波形 + `#f5a524` 播放游标。
- 区段：在波形上拖拽创建（默认当前标签）；选中后拖动整体平移、拖左右边缘伸缩；Delete 删除。
- 播放：整段 BufferSource + `startedAt` 偏移；播放游标 rAF 更新；点击波形定位；空格播放/暂停；选中区段时可循环试听（按钮）。
- 时间轴：自适应刻度（1/2/5/10/30/60 秒步长），显示 `mm:ss.s`。
- 保存前把 duration 回填到 meta（PATCH item meta）。

### 8.6 空间标注器

- 底图：`meta.bounds` 存在则用等距圆柱近似投影到视口（保持包围盒宽高比）；否则默认 `[0,0,1000,1000]`，坐标系 `pixel`。
- GeoJSON 源文件：拉取文本，绘制所有要素为背景轮廓（灰色），并自动以 bounds 适配。
- 栅格底图：绘制图片，像素 ↔ 经纬度线性映射。
- 工具：点（单击）、线（单击落点，双击结束）、面（单击落点，双击闭合）。Esc 取消当前草稿；Delete 删除选中要素。
- 命中：点在多边形内（射线法）或到线/点距离阈值。
- 面板显示光标经纬度；提供"配准"表单设置 W/S/E/N（EPSG:4326），保存至 meta。
- 导出 GeoJSON 时使用当前坐标系；像素坐标同样输出数字对，并在 crs 中注明。

### 8.7 工作台交互

- 三栏：左条目队列（搜索、状态过滤、我的队列、上传、分页）、中标注画布、右标签与标注列表 + 复核区。
- 顶部：项目名、kind、进度、导出、设置、返回。
- 底部：上一条/下一条、保存草稿、提交审核、快捷键提示。
- 保存：`Ctrl/Cmd+S`；提交：`Ctrl/Cmd+Enter`；未保存离开时提示（`beforeunload` + 切换条目确认）。
- 复核模式下（reviewer/manager 且条目 submitted）显示通过/驳回与意见框，并展示历史意见。
- 归档项目进入只读模式，隐藏写操作。

### 8.8 状态与错误呈现

- 列表加载：骨架行；空队列：说明 + 上传 CTA；无项目：说明 + 新建 CTA。
- 错误：顶部 toast（5s）+ 关键区域内的可重试提示；401 回登录；403 显示"无权访问"。
- 表单校验：字段下方红字；提交按钮在请求期间显示进度并禁用。
- 焦点可见；所有按钮有 hover/active/disabled 三态。

## 10. 关键流程时序

### 10.1 登录

```
client → POST /auth/login {username,password}
server → 查用户(active) → verify scrypt → 判限流
       → token=random(32) → insert sessions(sha256(token))
       → Set-Cookie；audit(login)
client ← 200 {user}
后续请求 Cookie → 摘要查询 → active 校验 → ctx.user
```

### 10.2 标注提交与复核

```
PUT /items/:id/annotation {data,submit:true}
  tx: upsert annotations(version+1,status=submitted)
      insert annotation_versions(version,data)
      update items.status=submitted
POST /items/:id/review {decision,note}
  tx: update annotations.status / item.status
      insert reviews
      insert annotation_versions(version+1,status=approved|rejected)
```

## 11. 失败模式与边界

| 场景 | 行为 |
|---|---|
| 数据库写冲突（SQLITE_BUSY） | busy_timeout 5s；仍失败返回 `503 DB_BUSY`，客户端可重试 |
| 磁盘满 / 写文件失败 | 删除临时文件，`500 STORAGE_ERROR`；不插入条目 |
| 文件被外部删除 | 下载 404 `FILE_MISSING`；条目保留，UI 提示重新上传或删除 |
| 图片尺寸解析失败 | 上传成功，meta 无尺寸；前端加载后回填 |
| 音频解码失败（浏览器不支持） | UI 明确提示支持格式，不阻塞其他条目 |
| 标签删除仍被引用 | `409 LABEL_IN_USE` 并列出引用条目数 |
| 并发覆盖标注 | 最后写入生效，version 递增，审计记录 updated_by；v1 不做乐观锁 |
| 非成员访问项目资源 | 403；不返回资源细节 |
| 停用账号持有会话 | 下一次请求即 401（join users 检查 status） |
| 路径穿越文件名 | 忽略客户端文件名路径部分，存储键服务端生成 |
| 超大 JSON / 上传 | `413 PAYLOAD_TOO_LARGE`，连接终止 |

## 12. 测试计划

### 12.1 单元

- 密码哈希/校验、错误密码、格式损坏。
- 标签体系校验（重复 id/name、非法颜色、悬空引用）。
- 图片尺寸解析（PNG/JPEG/GIF/WebP 样本）。
- GeoJSON 包围盒与坐标校验。
- 状态机非法迁移。

### 12.2 集成（`node:test`，临时数据目录）

1. 健康检查无需登录；未登录访问受保护 API → 401。
2. 管理员登录成功、错误密码 401、CSRF 缺失 403。
3. 创建用户与项目；非成员访问 → 403；加入成员后可访问。
4. 上传 PNG → meta 宽高正确；列表分页与过滤。
5. 保存草稿 → in_progress；提交 → submitted；版本快照存在。
6. 复核通过 → approved；导出 COCO 结构、类别/图片/标注数量正确；scope 生效。
7. annotator 调用复核 → 403；reviewer 通过后 annotator 修改 → 409（需 manager 重开）。
8. Range 请求音频 → 206 + Content-Range；非法范围 → 416。
9. 文本标注越界/重叠 → 422。
10. 登出后会话失效；停用用户会话立即 401。

### 12.3 浏览器端 E2E（`test/e2e.browser.test.js`，Chrome DevTools Protocol）

以真实浏览器驱动真实输入事件（`Input.dispatchMouseEvent` / `Input.dispatchKeyEvent`）走完整用户旅程，
不 Mock DOM。测试自建临时数据目录并播种演示数据，再拉起无头 Chrome 与临时 HTTP 服务：

1. 登录页：错误凭据给出提示，正确凭据进入项目列表。
2. 图片：鼠标拖拽画框 → 界面图元计数为 1 → 服务端落库且坐标落在图像范围内 → 提交复核 → 状态流转为 `submitted`。
3. 质检员：复核面板出现「通过 / 驳回」→ 点击通过 → 状态为 `approved`，复核记录写入。
4. 导出：导出弹窗提供 COCO 与范围切换；COCO 结果中的 `bbox` 与源条目上通过复核的矩形逐值一致。
5. 文本：鼠标拖选正文 → 标签浮层出现 → 点击标签 → 实体偏移与服务端一致 → 提交。
6. 音频：解码完成后拖拽波形新建区段 → 区段起止落在时长内 → 提交。
7. 空间：点要素工具落点 → 生成 Point 要素 → 提交。
8. 权限边界：标注员读取用户列表 → 403；进入管理台看不到任何用户行。
9. 全流程无未捕获异常、无控制台错误。

> 浏览器缺席（无 Chrome / Edge）时该套件整体跳过，不影响接口测试。

### 12.4 手工/浏览器验收

四种模态各完成：上传 → 标注 → 提交 → 复核 → 导出下载；检查 375/768/1440 宽度下布局与右侧面板折叠；检查空状态、加载态、错误提示、键盘焦点。
