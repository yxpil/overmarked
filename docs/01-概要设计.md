# OVERMARKED 数据标注工作台 — 概要设计

版本 1.0 · 2026-10-22 · 状态：已实现基线

---

## 1. 项目目标

OVERMARKED 是一个可私有化部署的多模态数据标注工作台。单人或小团队可以在同一套账号、权限与审核流程下，完成图片、文本、音频、空间矢量四类数据集的标注、复核与导出。

设计目标按优先级排序：

1. **开箱即用**：`npm start` 即可运行，零第三方运行时依赖，数据落在本地目录。
2. **权限边界清晰**：登录、会话、项目成员角色、审核动作全部在服务端强制校验。
3. **标注结果可交付**：每种模态都有标准导出格式（COCO / NER JSONL / 音频 JSONL / GeoJSON），同时保留无损原始 JSON。
4. **可审计**：关键写操作进入审计日志，标注与审核状态可追溯。
5. **界面像工具而非演示页**：信息密度高、键盘优先、无营销页噪音。

### 1.1 非目标（v1 明确不做）

- 不支持 3D 点云 / LiDAR / 视频逐帧标注。
- 不支持多人同时编辑同一条标注的冲突合并；采用"最后写入者胜出 + 版本号 + 审计"策略。
- 不内置对象存储、消息队列、外部 OAuth/LDAP。账号体系为本地账号。
- 不做模型辅助预标注、主动学习。
- 不做公网多租户 SaaS 隔离；定位是内网/团队单实例工具。

## 2. 角色与权限模型

### 2.1 系统级角色

| 角色 | 说明 |
|---|---|
| `admin` | 系统管理员。可管理全部用户、全部项目、查看全局审计。 |
| `user` | 普通账号。可见范围由其项目成员关系决定。 |

### 2.2 项目级角色（project_members.role）

| 角色 | 标注 | 复核 | 管理成员/标签/项目 | 删除项目 | 导出 |
|---|---|---|---|---|---|
| `manager` | ✓ | ✓ | ✓ | ✓ | ✓ |
| `reviewer` | ✓ | ✓ | — | — | ✓ |
| `annotator` | ✓ | — | — | — | —（可导出自己参与项目？v1 仅 manager/reviewer） |

规则：

- 创建项目者自动成为该项目 `manager`。
- 系统 `admin` 隐式拥有所有项目的 manager 权限，无需加入成员表。
- 项目成员只允许被管理员或该项目 manager 增删改。
- 任何项目数据（条目、文件、标注、统计、导出）都要求调用者至少是该项目的成员；非成员返回 `403`（不泄露项目是否存在返回 `404` 与否的差异——v1 使用 403，文档中说明）。
- 已归档项目对普通成员只读；manager/admin 可恢复。

### 2.3 权限判定伪代码

```
canManage(project)  = user.role == 'admin' || member.role == 'manager'
canReview(project)  = canManage(project) || member.role == 'reviewer'
canAnnotate(project)= canManage(project) || member.role in ('reviewer','annotator')
canView(project)    = user.role == 'admin' || member exists
```

## 3. 功能范围

### 3.1 账号与会话

- 用户名 + 密码登录；密码使用 `scrypt`（N=16384, r=8, p=1）加盐哈希，常量时间比较。
- 会话令牌 32 字节随机数，服务端只保存 SHA-256 摘要；HttpOnly + SameSite=Strict Cookie，默认 7 天。
- 登录失败限流：按 `IP + 用户名` 维度，10 分钟内最多 8 次失败。
- 修改密码；管理员可重置密码、停用账号。停用后既有会话立即失效。
- 首个管理员由服务启动时自动播种，密码来自 `ADMIN_PASSWORD` 或随机生成并写入 `data/initial-admin.txt`。

### 3.2 项目管理

- 创建项目时选择数据类型：`image | text | audio | spatial`，类型创建后不可更改。
- 标签体系（label schema）由项目维护：标签 id、名称、颜色、快捷键；文本项目额外支持"文档级标签"。
- 成员管理：增删成员、调整项目角色。
- 归档 / 恢复 / 删除项目。删除为硬删除（数据库记录 + 本地文件），需二次确认。

### 3.3 数据集与条目

- 条目 = 一个文件 + 元数据 + 状态 + 标注。
- 上传采用原始字节流接口，按项目类型校验扩展名与 MIME；单文件上限默认 512 MB（可配置）。
- 文件名只用于展示；磁盘使用 UUID 存储键，杜绝路径穿越。
- 图片条目上传时服务端解析 PNG/JPEG/GIF/WebP 头部，自动记录宽高。
- GeoJSON 条目上传时解析并记录经纬度包围盒，作为空间标注的坐标系基础。
- 条目支持按状态、关键词、指派人过滤；支持指派给项目成员。

### 3.4 四类标注

| 类型 | 标注能力 | 存储结构（annotation.data） | 标准导出 |
|---|---|---|---|
| 图片 `image` | 矩形框、任意多边形；选中、移动、缩放、顶点编辑 | `{shapes:[{type:'box',x,y,w,h,label} \| {type:'polygon',points:[...],label}]}` | COCO 1.0 |
| 文本 `text` | 字符区间实体（NER 风格）、文档级多标签 | `{entities:[{start,end,label}],documentLabels:[...]}` | JSONL（实体区间） |
| 音频 `audio` | 波形区段（起止秒）、区段移动/伸缩、试听 | `{segments:[{start,end,label}]}` | JSONL（秒） |
| 空间 `spatial` | 点 / 线 / 面矢量要素；地理参考栅格底图或 GeoJSON 底图 | `{features:[{geometry,label}]}` | GeoJSON FeatureCollection |

空间数据的定义为**二维地理参考矢量标注**：坐标系为 `EPSG:4326`（GeoJSON 底图）或 `pixel`（未配准栅格）。3D 点云不在 v1 范围内。

### 3.5 审核工作流

条目状态机：

```
pending ──保存草稿──> in_progress ──提交──> submitted ──通过──> approved
   ↑                     ↑                    │
   └────(manager 重置)────┴──────驳回──────────┘
                                        rejected ──修改并提交──> submitted
```

- 标注人保存草稿（`PUT annotation` 且 `submit=false`）→ `in_progress`。
- 标注人提交（`submit=true`）→ `submitted`，生成 annotation 版本记录。
- 复核人通过 → `approved`；驳回必须填写意见 → `rejected`。
- 已通过条目仅 manager 可重置回 `in_progress` 重新标注。
- 每次保存写入 `annotations` 主表（当前版本）+ `annotation_versions`（历史快照）+ 审计。

### 3.6 统计与导出

- 项目统计：各状态数量、通过率、按标注人计数、按标签计数、每日提交趋势。
- 导出作用域：`approved`（默认，只含已通过）或 `all`（含全部非空标注）。
- 导出为文件下载（`Content-Disposition: attachment`），图片项目可选 `coco` 或 `raw`，其他类型可选对应标准格式或 `raw`。

### 3.7 审计

记录：登录/登出/改密、用户创建修改、项目创建修改删除、成员变更、上传/删除条目、指派、标注保存/提交、复核决定、导出下载。审计记录包含操作者、动作、对象、摘要 JSON、IP、时间。管理员可查看全局审计，manager 可查看本项目审计。

## 4. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│ 浏览器 SPA（原生 ES Modules，无构建步骤）                     │
│  登录 / 项目列表 / 工作台                                     │
│  ├─ 标注器: image(canvas) text(span) audio(waveform) spatial  │
│  └─ API Client（fetch + Cookie + X-OM-Request 头）            │
└──────────────────────────┬───────────────────────────────────┘
                           │ HTTPS/HTTP  JSON + 原始字节流
┌──────────────────────────▼───────────────────────────────────┐
│ Node.js 24 单进程 HTTP 服务（node:http，路由自研）             │
│  ├─ 认证层  scrypt / session / 限流 / CSRF 头校验             │
│  ├─ 授权层  admin + project_members 角色矩阵                  │
│  ├─ 业务层  auth users projects items annotations stats export│
│  ├─ 文件层  流式上传 / 安全下载 / HTTP Range / 类型嗅探        │
│  └─ 审计层  同步写 audit_log                                  │
└───────────────┬──────────────────────────────┬───────────────┘
                │ node:sqlite (DatabaseSync)    │ fs
┌───────────────▼──────────────┐  ┌────────────▼───────────────┐
│ data/overmarked.db  (WAL)     │  │ data/uploads/<project>/... │
│ 用户/会话/项目/条目/标注/审计  │  │ 原始文件（UUID 命名）       │
└──────────────────────────────┘  └────────────────────────────┘
```

### 4.1 关键技术选择

| 决策 | 选择 | 理由 |
|---|---|---|
| 运行时 | Node.js ≥ 22.5（开发验证于 24.x） | 内置 `node:sqlite`、`fetch`、`node:test`，零依赖 |
| 数据库 | SQLite（`node:sqlite` DatabaseSync，WAL） | 单机部署、事务简单、备份即复制文件 |
| Web 框架 | 原生 `node:http` + 自研极简路由 | 无 npm 供应链面；路由数量可控 |
| 前端 | 原生 ES Modules + Canvas 2D | 无构建、离线可用；Canvas 足够四类标注 |
| 密码 | `crypto.scrypt` + 随机盐 | 标准 KDF，无外部依赖 |
| 会话 | 随机令牌 + DB 摘要 + HttpOnly Cookie | 可服务端吊销、支持"停用即下线" |
| 文件 | 本地磁盘 + UUID 键 + Range | 支持音频拖动播放、大文件流式上传 |

### 4.2 进程与部署形态

- 单进程，默认监听 `127.0.0.1:8787`；通过 `HOST=0.0.0.0` 开放内网访问。
- 数据目录 `DATA_DIR`（默认 `./data`）包含数据库、上传文件、首次管理员密码文件。
- 备份：停服或使用 SQLite 在线备份命令复制 `overmarked.db` + `uploads/`。
- 反向代理（Nginx/Caddy）负责 TLS 时，设置 `TRUST_PROXY=1` 以取 `X-Forwarded-For`。

## 5. 数据流

### 5.1 标注主流程

```
manager 建项目 → 配置标签 → 上传条目
      ↓
annotator 领取/被指派 → 打开工作台 → 加载文件(bytes/文本) → 编辑标注
      ↓ PUT /annotation (draft)                ↓ PUT /annotation (submit)
   item=in_progress                        item=submitted + annotation_versions
      ↓
reviewer 打开 submitted 队列 → 对照标注 → approve / reject(note)
      ↓
approved → 导出 COCO/NER/JSONL/GeoJSON → 交付
```

### 5.2 文件访问路径

1. 客户端 `GET /api/items/:id/file` 携带会话 Cookie。
2. 服务端校验登录 + 项目成员关系 + 项目归档状态。
3. 以存储键读取文件，按存储 MIME 返回；文本类强制 `text/plain; charset=utf-8`。
4. 音频/大文件支持 `Range`，返回 `206` 与 `Accept-Ranges: bytes`。
5. 响应头 `X-Content-Type-Options: nosniff`，SPA 页面附加 CSP。

## 6. 安全设计

| 风险 | 对策 |
|---|---|
| 密码泄露 | scrypt 加盐；恒定时间比较；登录限流；不记录明文 |
| 会话劫持 | HttpOnly + SameSite=Strict；令牌仅存摘要；改密/停用吊销会话；HTTPS 下 `Secure` |
| CSRF | SameSite=Strict + 所有非 GET API 要求 `X-OM-Request: 1` 自定义头 |
| 越权 | 每个项目路由统一 `requireProject(role)` 中间件；成员关系以数据库为准 |
| SQL 注入 | 所有查询使用预编译语句绑定参数 |
| 路径穿越 | 存储键由服务端生成 UUID；解析后路径必须位于上传根目录内 |
| 存储型 XSS | 前端只用 `textContent` 渲染用户数据；文本/JSON 文件强制纯文本响应 |
| 恶意上传 | 扩展名 + MIME 白名单、大小上限、流式写入临时文件后原子改名 |
| 暴力破解 | 登录失败滑窗限流；用户名不存在与密码错误返回同一错误 |
| 敏感信息 | 错误响应不返回堆栈；审计与日志不含密码/令牌 |

生产建议：置于 TLS 反向代理后；`DATA_DIR` 权限收紧；定期备份；管理员使用强密码。

## 7. 非功能设计

| 维度 | 目标 |
|---|---|
| 容量 | 单项目 10 万条目、单标注 5,000 个图元以内；v1 单实例 |
| 性能 | 列表分页 50 条/页；标注保存 P95 < 150ms（本地）；音频波形客户端降采样 |
| 并发 | SQLite WAL 允许多读单写；写操作短事务；同步 DB 调用在单进程内串行 |
| 可用性 | 进程崩溃后重启即可恢复；WAL 自动回放 |
| 兼容性 | Chrome/Edge 最新版；Firefox 最新版；Safari 17+ |
| 可维护性 | 后端按路由域拆分文件；前端按视图/标注器拆分；无构建链 |
| 可观测性 | 结构化请求日志（方法、路径、状态、耗时、用户）；`/api/health` |
| 可访问性 | 键盘可达、可见焦点环、语义化标签、对比度 ≥ 4.5:1 |

## 9. 里程碑与验收

| 阶段 | 交付物 | 验收标准 |
|---|---|---|
| M1 设计 | 本文件、详细设计、接口规范 | 文档与实现一致，无未定义接口 |
| M2 后端 | 认证/RBAC/项目/条目/标注/审核/导出 | `npm test` 集成用例全绿 |
| M3 前端 | 登录 + 项目 + 四类标注器 + 审核 | 浏览器实测四类标注各完成一次提交与审核 |
| M4 交付 | 演示数据、README、备份说明 | 新机器 `npm start` 后按 README 可复现 |

**完成定义（DoD）**：功能路径真实跑通、错误路径有明确状态码、文档命令可复制执行、无未使用的依赖与占位页面。
